# Docudis conformance fixtures

The v1 directory contains three language-neutral compatibility sources:

- `anonymization.json`: placeholder assignment, replacement, previous maps,
  person variants, disabled spans, and restoration.
- `rules.json`: 445 cases generated by the current Dart rule implementation,
  covering every bundled rule example, every region, validators, and curated
  checksum/syntax hard negatives.
- `pipeline.json`: 29 cases covering overlap priority, dictionary yielding, external NER merge,
  never-hide, birth-date defaults, repair, propagation, CJK, emoji, NBSP, and
  disabled detections.

Every detection and replacement records both:

- `start_utf8` / `end_utf8`: half-open UTF-8 byte offsets used by Rust and the
  public C ABI.
- `start_utf16` / `end_utf16`: half-open UTF-16 code-unit offsets used by Dart
  `String` APIs and the future Dart FFI adapter.

The Rust and Dart tests both consume this exact file. They verify every offset
pair by converting it from the source string before comparing anonymized text,
mapping order, replacement spans, and restoration output. Fixture schema
changes require a new version directory. The historical fixtures were
generated from the Dart reference implementation with:

```sh
dart run tool/generate_rust_rule_conformance.dart
dart run tool/generate_rust_pipeline_conformance.dart
```

Both generators carry Apache-2.0 notices and record their source in the JSON.
Authoritative rule data now lives in `data/rules`; the rule data retains the
DocCloak.Core attribution in `LICENSE-DocCloak.Core` and
`NOTICE-DocCloak.Core`.

## Regex compatibility decisions

Rust uses `fancy-regex` for the consuming expression so Unicode classes,
lookahead, case flags, multiline mode, captures, zero-width assertions, and
the French-phone separator backreference retain the current semantics. The
engine cannot compile variable-width lookbehind. Leading lookbehinds are
therefore split into a consuming candidate plus a Rust prefix guard:

| Rule families | Rewrite reason |
| --- | --- |
| labelled IDs, BIC, labelled companies | variable-length label before value |
| BE/CH postal-city | start-of-text or separator alternatives have different widths |
| credit card, short date, ES/FR postal | bounded negative context has variable width |

Rejected guards restart matching at the next Unicode scalar rather than the
end of the rejected candidate. This is necessary when an earlier broad
candidate begins inside the label itself. `rules.json` compares type, value,
enabled state, confidence, source, detector id, and both offset systems in
Dart and Rust, so these rewrites are evidence-backed rather than assumed.
